# 剧本贡献指南

剧本是 JSON 配置，不是程序代码。只要按本指南填写，换一个剧本通常不用修改代码。欢迎老师贡献新的教学情境、角色和讨论线索。

## 一、剧本文件

把剧本保存为 `backend/scripts/你的剧本 id.json`。文件名以 `.json` 结尾，`id` 必须唯一；系统启动时会自动读取这个目录中的剧本。

### 1. 顶层字段

| 字段 | 填什么 |
| --- | --- |
| `_comment` | 给维护者看的说明，可写版本、假设和校准提醒。它不会参与剧情。工程数据包含数字时，请保留“待校准”说明。 |
| `id` | 剧本的英文或数字标识，例如 `handong`；不能和已有剧本重复。 |
| `title` | 教师和学生看到的剧本名称。 |
| `company` | 情境中的公司或组织名称。 |
| `background` | 开局背景、任务目标和主要约束，写给学生看的简介。 |
| `duration` | 建议完成时长，例如 `30–45 分钟`。 |
| `roles` | 学生可选择或分配的岗位列表。见下文。 |
| `rules` | 预算、工期、核心指标和触发阈值等游戏规则。见下文。 |
| `routes` | 学生可以选择的主要方案路线。每条路线写清成本、工期和对指标的影响。 |
| `specialActions` | 访问现场、跟车检查等额外行动。 |
| `acts` | 剧情幕次和每一幕的推进条件。 |
| `dialogTopics` | 对话主题及关键词，帮助系统识别学生正在询问什么。 |
| `npcs` | 非玩家角色列表，每个 NPC 关联一张角色卡。 |
| `evaluationDimensions` | 教学评价维度，例如问题定位、约束意识、方案完整度。 |
| `calibrationItems` | 需要专家或课堂试跑后核准的数字、岗位和假设。 |
| `directorCardId` | 导演角色卡的 `id`，必须对应 `backend/scripts/cards/` 中的卡片。 |
| `world_info` | 关键词触发的隐藏剧情，见第三节。 |
| `director_dispatch` | 结构化事件发给哪个 NPC，例如客户施压、财务预警。引用的 `npcId` 必须存在。 |

### 2. 关键子结构

`roles` 中每项通常包含：

- `id`：岗位短名，如 `方案`、`测试`、`质检`。
- `title`：岗位全称。
- `opening`：该岗位开局拿到的任务或信息。
- `information`：该岗位掌握的资料清单。

`rules` 中常用字段如下：

| 字段 | 含义 |
| --- | --- |
| `budgetLimit` | 总预算上限。 |
| `scheduleLimit` | 工期上限，通常以天为单位。 |
| `clientTrust` | 初始客户信任度。 |
| `metric` | 核心指标对象：`key` 是程序用的英文名，`name` 是显示名，`unit` 是单位，`initial` 是初始值，`target` 是目标值。 |
| `metric.direction` | `min` 表示最终值至少达到目标；`max` 表示最终值不得高于目标。 |
| `financeWarningThreshold` | 触发财务提醒的阈值。 |
| `clientPressureThreshold` | 触发客户施压的阈值。 |
| `clientTrustPenalty` | 触发失误时扣除的信任度。 |
| `ineffectiveTurnThreshold` | 连续多少次无效行动后提醒或推进事件。 |
| `calibration`、`eventsCalibration` | 标记尚未由工程或课堂数据核准的内容，写 `待校准`。 |

`routes` 每项建议包含：`id`（唯一标识）、`action`（动作名）、`label`（显示名称）、`description`（给学生看的说明）、`budget`（成本）、`schedule`（工期）、`metricChange`（对核心指标的变化）、`flag`（选择后留下的状态标记）和 `calibration`。

`specialActions` 可包含 `action`、`label`、`flag`、`information`、`metricChange`、`calibration`。`acts` 可包含 `number`、`name`、`durationMs`（毫秒）、`hint`、`advance` 和 `calibration`。

`dialogTopics` 用 `topic` 标识主题，用 `pattern` 写正则样式的关键词字符串，例如 `预算|成本|报价`。`npcs` 至少要写 `id`、`cardId`、`aliases` 和 `visibleFields`；其中 `cardId` 必须能找到对应角色卡，`visibleFields` 决定该 NPC 可看到哪些状态。

## 二、角色卡文件

把角色卡保存为 `backend/scripts/cards/角色卡文件名.json`。`id` 必须唯一，并且要和剧本 `npcs[].cardId` 或 `directorCardId` 完全一致。角色卡是角色的边界，不是让角色随意补充事实的提示词。

### 1. 必填字段

| 字段 | 填什么 |
| --- | --- |
| `_comment` | 给维护者看的用途或版本说明。 |
| `id` | 唯一标识。 |
| `name` | 角色显示名。 |
| `身份` | 角色在公司中的身份。 |
| `目标` | 角色希望推动的结果。 |
| `性格` | 角色的稳定性格和反应方式。 |
| `知识边界` | 必须包含 `知道` 和 `不知道` 两个非空数组；明确角色能说什么、不能知道什么。 |
| `语言风格` | 句式、语气和专业程度。 |
| `红线` | 必须是非空数组；写明不能泄露、不能承诺或不能越权的内容。 |
| `开场白` | 角色第一次出现时的说法。 |
| `示例对话` | 必须正好有两轮，每轮都有非空的 `user` 和 `assistant`。 |

### 2. 最小角色卡示例

```json
{
  "_comment": "示例客户卡；数字和事实待校准。",
  "id": "sample-client",
  "name": "周经理",
  "身份": "客户调度经理",
  "目标": "在预算内尽快降低货损。",
  "性格": "着急但愿意听证据。",
  "知识边界": {
    "知道": ["配送时段", "客户投诉"],
    "不知道": ["学生尚未询问的供应商底价", "剧本之外的事实"]
  },
  "语言风格": "简短、具体，优先回答可执行问题。",
  "红线": ["不直接给出最优方案", "不编造未经确认的数字"],
  "开场白": "请先告诉我问题有多严重，以及预算和工期。",
  "示例对话": [
    {"user": "目前最急的约束是什么？", "assistant": "先把货损控制住，但预算和交付日期也不能失守。"},
    {"user": "能保证一定达到目标吗？", "assistant": "请先拿出依据和风险预案，我不能替你承诺未知结果。"}
  ]
}
```

## 三、World Info：关键词触发隐藏剧情

在剧本的 `world_info` 数组中，每项写 `id`、`keywords`、`npcIds` 和 `content`：

- `id`：条目唯一标识。
- `keywords`：关键词数组。系统会把学生本轮原文转成小写，只做字面包含匹配；不是语义理解，也不是模糊匹配。
- `npcIds`：允许看到该条目的 NPC id 数组；留空或省略表示不限制 NPC。这里的 id 必须来自本剧本的 `npcs`。
- `content`：命中后提供给角色的隐藏背景信息。

例如，学生与 `client` 对话并说到“夜间收货”时，系统会注入下面内容：

```json
"world_info": [{
  "id": "night-window",
  "keywords": ["夜间", "错峰"],
  "npcIds": ["client"],
  "content": "隐藏线：部分门店有夜间收货窗口，但要学生主动提出配送调整才说明。"
}]
```

关键词要写学生可能实际说出的词，并避免过于常见的单字；同一条目可以有多个关键词，命中任意一个即可。重复命中相同内容时，系统只呈现一次。

## 四、贡献流程与校准规矩

1. Fork 本项目，在自己的分支中新增或修改 JSON。
2. 按本指南填写剧本和角色卡，保持 `id`、`cardId`、`npcIds` 的引用一致。
3. 自查 JSON 格式、字段拼写、数字单位和剧情是否能从开局走到结算；尤其确认每个 NPC 和导演卡都能找到对应角色卡。
4. 提交 Pull Request；如果暂时不会提交代码，也可以提 Issue，附上剧本目的、完整 JSON 或草稿和希望讨论的教学目标。

工程数据必须标注“待校准”：成本、工期、指标初值/目标、路线效果、阈值、事件强度、岗位设置等，只要不是经过工程资料或课堂试跑确认的内容，都要在相关对象中保留 `"calibration": "待校准"`，并在顶层 `_comment` 或 `calibrationItems` 中说明。不要为了让示例看起来完整而伪装成精确事实；校准完成后再由维护者移除或更新标记，并在 PR/Issue 中说明依据。

## 五、提交前快速检查

- 文件是合法 JSON，且没有把注释放进 JSON（说明请写 `_comment`）。
- `id` 唯一；NPC 的 `cardId`、World Info 的 `npcIds` 和导演卡 id 都有对应对象。
- 角色卡包含全部必填字段，`知识边界` 有 `知道`/`不知道`，`示例对话` 恰好两轮。
- `metric.direction` 只使用 `min` 或 `max`，并确认指标变化方向符合目标。
- 所有工程数字都明确标注“待校准”。
