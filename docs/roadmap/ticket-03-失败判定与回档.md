# Ticket 03：失败判定与回档

## 目标

统一失败分类、失败后的复盘闭环、严格一次回档和超时交付规则，保证失败结果可解释、可复核且不被误称为“通关”。

## 范围

### 做什么

- 定义四类失败：方案被否（硬约束不满足或缺少纠正/预防）、超时无方案、预算失控、合规失败。
- 将无证据调账、虚构盘点、越权承诺列为合规失败信号，并规定教师端必须复核。
- 定义失败后的默认结果为“复盘闭环完成”，保留雷达图、证据摘要、失败链条和反思任务，不使用“通关”表述。
- 定义严格一次回档：仅第三幕前、剩余不少于约 5 分钟、错误尚未执行、且未触及合规红线时允许；回档保留原决定和返工原因。
- 规定重开仅能由教师在课后启动；超时后改交“暂缓决策报告”。

### 不做什么

- 不实现教师端复核流程、回档界面、重开操作或报告模板。
- 不允许学生自行删除、覆盖或隐藏原决定与失败证据。
- 不将合规失败自动改写为一般性失败，或绕过教师复核。

## 验收标准

- 任一失败记录均能归入四类之一，并保留对应的判定依据与证据摘要。
- 触发无证据调账、虚构盘点或越权承诺时，结果标记为合规失败并进入教师端必复核队列。
- 失败结算产物显示“复盘闭环完成”，并包含雷达图、证据摘要、失败链条和反思任务，且不显示“通关”。
- 回档仅在四项条件同时满足时开放，且每个会话最多一次；回档记录可查到原决定和返工原因。
- 超时后不再回到正常方案流程，改为提交“暂缓决策报告”；重开权限仅在教师课后流程中可用。

## 技术思路

- 建立失败判定枚举与证据对象，将硬约束、时间、预算和合规信号分别归档，合规类额外产生教师复核状态。
- 失败结算采用不可变快照，输出评价雷达图、证据摘要、失败因果链和反思任务；状态名称与产品文案统一为“复盘闭环完成”。
- 回档采用受限状态迁移守卫：验证幕次、剩余时间、执行状态、合规标记及已用回档次数；成功后追加而非覆盖决策历史。
- 将重开动作置于教师授权的课后管理域，超时场景路由至“暂缓决策报告”交付状态。
