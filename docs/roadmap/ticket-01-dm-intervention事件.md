# Ticket 01：新增 `dm_intervention` 事件

## 目标

建立可审计的 DM 干预事件记录，使六维评价能够查看干预发生前后学生行为的变化，同时确保 DM 干预本身不被当作处罚或扣分依据。

## 范围

### 做什么

- 定义 `dm_intervention` 事件及其字段：`priority`、`trigger`、`action`、`state_change`、`scoreImpact`。
- 将 `scoreImpact` 固定为 `none`，不允许 DM 干预事件直接产生分数增减。
- 记录触发干预时的学生行为上下文，以及干预后的学生行为变化，供六维评价回溯和取证。
- 明确事件语义：DM 是改变时间压力、信息压力和流程边界的环境状态机，不提供根因或最优方案。

### 不做什么

- 不在本票据中实现事件采集、存储、评价计算或前端展示。
- 不把触发干预、接受干预或未立即响应干预直接映射为负向评分。
- 不让 DM 通过事件字段提供事实之外的新信息、根因分析或最优解法。

## 验收标准

- `dm_intervention` 的数据契约包含且仅以 `priority`、`trigger`、`action`、`state_change`、`scoreImpact` 作为规定字段；`scoreImpact` 的值固定为 `none`。
- 每次干预均能关联干预前行为快照、干预动作和干预后行为变化，支持六维评价按证据回溯。
- 评价规则不会因为存在 `dm_intervention` 事件本身而扣分或加分；只有学生在干预后的自主行为可成为评价证据。
- 事件说明明确 DM 干预是环境变化而非处罚，且不会泄露根因或最优方案。

## 技术思路

- 在统一事件模型中增加可版本化的 `dm_intervention` 事件类型，将五个字段作为稳定载荷；其中 `scoreImpact` 使用字面量约束 `none`。
- 以会话时间线或行为事件 ID 建立前后窗口引用：事件只保存必要的关联信息，评价侧再读取学生行为证据并计算六维结果。
- 将“DM 事件不得直接计分”固化为评价管线的输入约束或过滤规则，并在审计输出中区分“干预记录”与“学生行为证据”。
