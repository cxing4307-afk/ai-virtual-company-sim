## 我们在解决什么问题

很多工科学生毕业进了企业才发现：学校里学的"最优解"，在企业里要让位于成本、工期、风险和盈利。**而企业几乎不给新人试错的机会**——搞砸一个项目，损失是真金白银。

我们希望让学生在一节课里完成一次真正的工程实践，并自动留下可复查的教改证据：

- 学生以员工身份**单人单岗闯关**（不组队——一知半解凑不出项目味）
- AI 扮演甲方、供应商、财务、老师傅等**所有其余角色**，还兼任"**导演**"把控节奏
- 一节课（30–45 分钟）做完一个完整项目：接单 → 调研 → 交方案；关键决策、状态变化与过程评价可供教师复盘
- 预算超了怎么办？甲方催了怎么办？方案搞砸了——**没关系，重开一局。失败本身就是评分的一部分**

**仿真不求逼真，只求把决策的约束结构搭对。** 目标不是"实验室最优"，而是"工程最适配"；课堂过程也因此成为可核查、可复用的教改证据。

## 核心设计（如何让实践与证据在同一节课里完成）

| 设计 | 含义 |
|---|---|
| 剧本杀结构 | DM（导演/上帝视角）+ 留白 + 单真实玩家 + 全 Agent NPC |
| NPC 独立提示词 | 每个角色有身份、目标、性格、知识边界、语言风格、红线；只按角色聊天，**不直接给学生答案** |
| 确定性规则引擎 | 预算、工期、信任度等硬状态**只能由规则改变**，AI 只负责"演"，不决定"发生什么"——让课堂过程可复盘、可评分、可核查 |
| 允许失败 | 搞砸 = 不通关，可重开。企业里没有这种机会，这是这个工具最好的地方 |
| 多维过程性评价 | 不打总分。看沟通、约束意识、尝试次数——**评估过程质量，而非答案对错** |
| 剧本与引擎分离 | 剧本是 JSON 配置，换剧本不用改代码。老师可以写自己的剧本 |

## 现状（Demo 可玩）

- 两个剧本：《寒冬订单》（燃料电池公交冬季续航衰减）、《高温订单》（冷链车制冷不足）
- 10 个 NPC + 导演，完整三幕流程，六维评价 + 教师复盘页（决策时间线、状态曲线）
- 剧本、角色卡、World Info（关键词触发隐藏剧情）全部 JSON 配置化

```bash
npm install
npm start
# 浏览器打开 http://localhost:3000
# 在首页填入 DeepSeek API Key（只存服务器内存，关闭即失）
```

详细玩法见 [运行说明.md](./运行说明.md)。所有工程数字为示意数据，标注"待校准"。
